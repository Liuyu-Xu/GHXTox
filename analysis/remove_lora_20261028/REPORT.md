# 移除LoRA：变更与验证

按用户决定，默认新训练改为冻结ProtT5 + 双向Mamba，不再创建LoRA层，参数配置为 `configs/no_lora_mamba_1d_autodl.json`（本地备用`configs/no_lora_mamba_1d.json`）。`cv`和`full`不指定配置时使用无LoRA配置；明确指定历史配置仍为兼容历史实验。

现有公开模型的三份历史权重保存了零LoRA矩阵。为确保旧权重仍可加载，推理先根据旧配置严格校验并加载，再确认所有LoRA B矩阵均为零后物理移除144个LoRA层。若存在非零B，函数在移除任何模块前报错，避免静默丢失信息。原始权重、校准与融合阈值未改。

实测三份真实ProtT5权重、每份4条序列，删除前后的GPU fp16 logits差为0；另用真实ProtT5运行一批无LoRA训练，编码器无梯度、分类头参数更新，新的checkpoint结构校验通过。小模型回归测试涵盖零LoRA等价、非零LoRA拒绝、无LoRA权重契约。

删除不会让历史指标自动提高；四折单种子初筛未观察到稳定收益，不能证明其他训练场景LoRA一定无效。此次未重新训练完整三种子模型。

项目合同测试中，`configs/hndp_v1_protocol.json` 原有JSON格式错误使配置全量扫描测试失败；该文件与此次变更无关，未修改。其余相关测试见最终测试记录。
